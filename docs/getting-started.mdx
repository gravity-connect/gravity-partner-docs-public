Welcome to the Gusto API documentation. This page provides an overview of our API, its capabilities, and how to get started.

## Overview

The Gusto API is a RESTful API that lets you programmatically access payroll, benefits, and HR data. It uses standard HTTP methods, returns JSON-encoded responses, and authenticates via OAuth 2.0.

All API endpoints are defined using the OpenAPI 3.0 specification, so you can generate client libraries, validate requests, and explore endpoints interactively.

## Base URL

```
https://api.gusto.com/v1
```

A sandbox environment is available for testing:

```
https://api.gusto-demo.com/v1
```

## Authentication

The API uses OAuth 2.0 for authentication. Every request must include a valid access token in the `Authorization` header:

```
Authorization: Bearer YOUR_ACCESS_TOKEN
```

See the [Authentication guide](#) for details on obtaining and refreshing tokens.

## Key Features

- **Payroll** — Run payroll, retrieve pay stubs, and manage pay schedules.
- **Employees** — Create, update, and onboard employees.
- **Benefits** — Manage health insurance, retirement plans, and other benefits.
- **Companies** — Access and update company-level information.
- **Webhooks** — Subscribe to real-time events across your account.

### Rate Limits

Requests are limited to **200 requests per minute** per access token. Responses include rate-limit headers:

| Header | Description |
| --- | --- |
| `X-RateLimit-Limit` | Maximum requests per window |
| `X-RateLimit-Remaining` | Requests remaining in the current window |
| `X-RateLimit-Reset` | Time when the window resets (Unix epoch) |

Exceeding the limit returns a `429 Too Many Requests` response.

## Versioning

The API is versioned via the URL path (e.g., `/v1`). Breaking changes are introduced under new version numbers, and deprecated versions are supported for at least 12 months after a successor is released.
